# SPXQuery Version 0.3.0 Changelog

**Release Date**: 2026-05-18
**Git Tag**: v0.3.0

## New Module: `spxquery.batch`

Multi-source batch photometry pipeline for processing many sources across SPHEREx full-frame images in a sky region.

### Public API

**src/spxquery/batch/__init__.py**

- `BatchConfig`: Region-based query configuration (center RA/Dec, radius, catalog, filters)
- `BatchPipeline`: Four-stage pipeline (query → download → extract → aggregate)
- `run_batch()`: One-function convenience wrapper
- `load_query_summary()`: Load saved query metadata from YAML

### Configuration

**src/spxquery/batch/config.py**

- `BatchConfig` dataclass with region, query filters, parallelism, and photometry parameters
- `load_catalog()`: Load CSV catalog (`targetid, ra, dec`) into `Source` objects
  - Reads `targetid` as string to prevent float64 precision loss for large integers

### Query

**src/spxquery/batch/query.py**

- `query_region_observations()`: ADQL spatial query with INTERSECTS (any overlap) or CONTAINS (full coverage) modes
- Band filtering (`bands=["D3", "D4"]`), MJD time filtering (`mjd_range`), and `max_images` safety gate
- Saves query metadata to `query_summary.yaml` with region, filters, band counts, and per-observation details

### Extraction

**src/spxquery/batch/extract.py**

- `process_single_image()`: Optimized per-image extraction with pre-computed shared arrays, batch WCS projection, local cutout photometry, and combined bitmask flag filtering
- `run_extraction()`: `mp.Pool` with spawn workers, `imap_unordered` + tqdm progress, resumable via `skip_existing`

### Aggregation

**src/spxquery/batch/aggregate.py**

- `aggregate_lightcurves()`: Two-phase bucket aggregation (blake2b hash partitioning) for memory-efficient per-source light curve generation
- `_tid_to_filename()`: Defensive target_id formatting to prevent scientific notation in filenames

### Pipeline

**src/spxquery/batch/pipeline.py**

- `BatchPipeline` class with independent stage methods (`run_query`, `run_download`, `run_extract`, `run_aggregate`) and `run_all()`
- `run_batch()` convenience function
- `_save_query_summary()`: YAML serialization with numpy → Python type conversion
- `load_query_summary()`: Reload query metadata from disk

### Bug Fixes

- Fixed target_id being written in scientific notation (float64 precision loss) in per-image CSVs and lightcurve filenames — `load_catalog` reads `targetid` as string, aggregate uses `_tid_to_filename()` formatter
- Fixed `yaml.safe_load` failure when query metadata contained numpy scalar types — explicit `float()`/`int()` conversion in `_save_query_summary()`

### Documentation

- `docs/user_guide/batch_photometry.md`: Full user guide with configuration reference, coverage modes, filtering, pipeline stages, output structure
- `docs/api/batch.md`: API reference
- `example/batch_demo/batch_photometry_demo.ipynb`: End-to-end demo with real DESI NEP sources

### Design

- Purely additive module — no modifications to existing `spxquery` code
- Data flow: region query → full-frame download → multi-source extraction → bucket aggregation
- Does not reuse or extend `SPXQueryPipeline` (single-source design)
